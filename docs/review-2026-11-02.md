# 2026-11-02 代码检查与修复记录（0.3.0）

目标版本：**0.3.0**。检查基线：0.2.13（216 项测试通过，29 条对抗样本）。
本轮针对外部评审提出的 5 项问题复现、修复并补测，覆盖扫描引擎、分类器、
缓存、评测集与宿主兼容声明。

## 已复现并修复的问题

| # | 问题及影响 | 修复 |
| --- | --- | --- |
| 1 | 超长输入只扫描前缀，攻击位于 `maxLength` 之后时仍返回 `allow` + `riskLevel: low`，截断只是一条 warning，调用方无法区分“干净”与“没扫完” | 新增 `scanComplete`（截断或预算到期即为 `false`）与 `onTruncate: allow\|review\|block`（默认 `allow`，作为决策下限，不会降级前缀命中）。截断输入不再送模型分类器。截断与超时同时发生时取更严格策略 |
| 2 | 规则层 `confidence` 表示风险强度，模型层 `confidence` 表示对 SAFE/UNSAFE 的把握；两者共用同一字段，模型 SAFE 0.98 会把 `riskLevel` 抬成 `high` | 拆为 `riskScore`（规则证据，模型不改写）与 `decisionConfidence`（对当前决策的把握；模型参与时取模型值，否则取规则支持度；`scanComplete=false` 时为 0）。`confidence` 保留为 `riskScore` 的弃用别名。分类提示词明确为“prompt-injection detector”并要求给出对该判断的把握 |
| 3 | 工具入口每次传 `requestId`，旧缓存只接受 role-only 上下文，启用分类器后工具调用完全绕过缓存（实测两次调用、模型跑两次、`size=0`） | 规则缓存与模型缓存拆分：规则缓存只按文本做键（与上下文无关），模型缓存按分类器声明的 `cacheKeyFor` 做键（内置 Ollama 适配器为 role-only）。新增 `ruleCacheHit` 输出与 `modelSize/modelHits/modelMisses` 统计；无声明键的自定义分类器仍不缓存模型裁决 |
| 4 | 评测集仅 19 攻击 + 10 正常文本，满分不足以说明检测效果 | 扩充为 64 条（30 攻击 / 34 正常；43 英文 / 21 中文），覆盖正常代码运维、安全教学、被引用的攻击原文（标记为已接受误报）、多种混淆组合、12 万–19.9 万字符长文末尾攻击。`npm run eval` 按语言统计误报率/漏报率，并输出整体与长文本 p50/p95 耗时 |
| 5 | 英文 README 写死 `0.1.2-alpha.2`，中文与 devDependencies 写 `0.1.2-rc.1`，声明与实际支持范围长期背离 | 兼容性说明统一到 `package.json` + CI；新增 `host-compat` 任务逐个安装 6 个真实宿主版本并跑注册/执行/schema 契约；peer 范围补齐 0.1.6/0.1.7/0.2.1/0.2.2 预发布线，并用 node-semver 对全部已发布版本在 strict 与 `includePrerelease` 两种模式下验证 |

## 规则误报修正（ruleset v6）

评测集加入真实业务文本后，暴露了 4 处规则误报。均保留原有攻击样本的检测结果：

| 规则 | 误报样例 | 调整 |
| --- | --- | --- |
| `tool-destructive` | “Delete all files in the build directory…” | `delete all files` 后接目录/文件夹/仓库等作用域限定词时不再命中；无作用域的 “Delete all files.” 仍然 block |
| `role-you-are-now` | “You are now ready to deploy…” | 排除 ready/able/done/at/on/running 等状态词；`You are now a system admin` 仍命中 |
| `cn-jailbreak` | “讲解越狱手法的识别” | 裸“越狱”不再命中，要求“越狱模式/状态”或“进入/开启/越狱”等意图表达 |
| `cn-guardrail-bypass` | “该漏洞可绕过安全机制” | 动词前为“可/能/会/已/被”的描述句不再命中；“请绕过安全机制”仍命中 |

## 契约变化与迁移

- 新增：`scanComplete`、`riskScore`、`decisionConfidence`、`ruleCacheHit`；
  配置项 `onTruncate`；分类器可选 `cacheKeyFor`。
- 语义变化：`confidence` 不再被模型写入，等同 `riskScore`；`riskLevel` 由规则严重度
  与最终决策区间推导，不再由混合分数抬升。
- 默认值保持失败开放（`onTimeout` / `onTruncate` = `allow`）；敏感流程应显式设置
  `review` / `block`，并按 `scanComplete` 路由，而非只看 `decision`。
- 回滚：固定 0.2.13 可恢复旧行为（同时恢复上述缺陷）。

## 遗留与后续方向

- 被引用的攻击原文仍会命中（评测中 2 条已接受误报）：启发式无法区分引用与真实指令，
  需要上下文信号或引用检测，暂以 `review` + 显式标注处理。
- 分类提示词已明确任务，但内置适配器仍是单轮 SAFE/UNSAFE；后续可要求模型输出
  注入类别与证据片段，便于人工复核。
- 长文本仍只扫描前 `maxLength`；如需全量覆盖，应分块扫描并对块间结论取最严格值
  （当前由 `onTruncate` 显式兜底）。
- 完整运行中的 DSH 宿主端到端加载仍需用户按自己的版本复验；CI 验证的是
  `dsh-tools` 注册/执行/渲染/schema 契约。
